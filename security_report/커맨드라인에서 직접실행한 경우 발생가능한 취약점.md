네 코드에서

spawn("python", [
  "faster_whisper_test.py",
  TEST_AUDIO,
  "results/faster.srt"
]);

의 TEST_AUDIO가 사용자 입력이라면, OWASP Top 10 기준으로는 주로 다음과 관련 있어.

A03:2021 - Injection

가장 직접적인 관련이 있음.

예를 들어:

exec(`python faster_whisper_test.py ${userInput}`);

사용자가

audio.mp3 && rm -rf /

같은 값을 넣으면

python faster_whisper_test.py audio.mp3 && rm -rf /

가 실행될 수 있음.

대표적인 종류:

OS Command Injection
SQL Injection
NoSQL Injection
LDAP Injection

네 경우는 OS Command Injection.

A01:2021 - Broken Access Control

파일 이름을 사용자가 조작할 수 있다면:

../../../secret.txt

같은 경로 조작이 가능할 수 있음.

예:

spawn("python", [
    script,
    userPath
])

사용자가

../../../../windows/system32/drivers/etc/hosts

를 넣으면 의도하지 않은 파일을 읽게 될 수도 있음.

이건

Directory Traversal
Path Traversal

과 관련됨.

A05:2021 - Security Misconfiguration
spawn(command, args, {
    shell: true
})

처럼 쉘을 불필요하게 활성화하면 설정 자체가 위험해짐.

A04:2021 - Insecure Design

파일명을 그대로 신뢰하는 설계:

outputPath = req.body.filename;

같은 것.

근본적으로

사용자 입력
↓
파일 시스템 접근
↓
외부 프로세스 실행

이 연결되어 있으면 설계상 위험성이 커짐.

네 경우에 가장 중요한 것
1위
A03 Injection

(OS Command Injection)

2위
A01 Broken Access Control

(Path Traversal)

안전한 설계

사용자:

mp4 업로드

↓

서버:

jobId = uuid()

↓

서버 내부:

backend/uploads/jobs/{jobId}/audio.mp3
backend/uploads/jobs/{jobId}/transcription.srt

↓

spawn("python", [
    scriptPath,
    audioPath,
    srtPath
], {
    shell: false
})

즉,

사용자가 파일 이름이나 경로를 결정하지 못하게 하는 것이 가장 중요해.

사실 네가 만들고 있는

React
↓
Express
↓
FFmpeg
↓
Whisper
↓
SRT

구조에서 보안적으로 가장 위험한 부분은

FFmpeg와 Python 프로세스를 실행할 때 사용자 입력이 어느 정도까지 영향을 미치는가

이고, 이것은 OWASP Top10의 A03 Injection과 가장 밀접하게 관련되어 있어.
