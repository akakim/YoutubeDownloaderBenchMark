현업에서는 WebView를 그냥 웹페이지 띄우는 화면으로만 보지 않고, 보통 네이티브 껍데기 + 웹 서비스 구조로 씁니다.

XX님 상황이면 아마 이런 구조가 가장 자연스럽습니다.

Android App
 ├─ 네이티브 기능
 │   ├─ 파일 선택
 │   ├─ 공유
 │   ├─ 알림
 │   ├─ 다운로드
 │   └─ 기기 정보
 │
 └─ WebView
     └─ React 화면
         └─ Express 웹서버/API
현업에서 흔한 사용 방식
1. 기존 웹서비스를 앱으로 감싸기

React 웹서비스가 이미 있다면 가장 빠른 방법입니다.

webView.loadUrl("https://service.example.com")

UI와 비즈니스 로직은 웹에서 관리하고, 앱은 WebView와 일부 네이티브 기능만 담당합니다.

장점은 웹 배포만으로 화면을 업데이트할 수 있다는 점입니다. WebView는 앱이 통제하는 웹 콘텐츠를 앱 내부에 넣고 빠르게 업데이트할 때 적합합니다. 외부 사이트를 단순히 여는 용도라면 Google은 WebView보다 Custom Tabs를 권장합니다.

2. 웹과 네이티브를 브리지로 연결하기

예를 들면 React에서 파일 선택을 요청하면 Android가 파일 선택기를 여는 방식입니다.

React
  ↓ "파일 선택해줘"
Android WebView Bridge
  ↓
Android 파일 선택기
  ↓
선택 결과
  ↓
React

예전 방식은 다음과 같습니다.

class AndroidBridge {

    @JavascriptInterface
    fun openFilePicker() {
        // Android 파일 선택기 실행
    }
}

webView.addJavascriptInterface(
    AndroidBridge(),
    "Android"
)

웹에서는:

window.Android?.openFilePicker()

다만 addJavascriptInterface()는 모든 iframe에서도 접근할 수 있고 호출 프레임의 출처를 확실하게 검증하기 어렵습니다. 따라서 자신이 관리하는 도메인만 로드할 때 제한적으로 써야 합니다. 가능하면 AndroidX WebKit의 메시지 채널 계열을 검토하는 편이 안전합니다.

아쿠아 헤르메스님 프로젝트에 맞는 구조

쇼츠헌터 같은 도구라면 네이티브가 담당하기 좋은 기능은 다음입니다.

React WebView 화면
 ├─ 영상 목록과 편집 UI
 ├─ 자막 편집
 ├─ 프로젝트 설정
 └─ 서버 API 호출

Android 네이티브
 ├─ 갤러리에서 영상 선택
 ├─ 파일 시스템 접근
 ├─ 공유 인텐트
 ├─ 백그라운드 다운로드
 ├─ 알림
 └─ FFmpeg 작업 상태 표시

즉, 화면과 서비스 로직은 React, 운영체제에 가까운 기능은 Android가 맡는 겁니다.

기본 구현 예시

Compose를 쓴다면:

@Composable
fun WebAppScreen(
    url: String
) {
    AndroidView(
        factory = { context ->
            WebView(context).apply {
                settings.apply {
                    javaScriptEnabled = true
                    domStorageEnabled = true

                    allowFileAccess = false
                    allowContentAccess = false
                    mixedContentMode =
                        WebSettings.MIXED_CONTENT_NEVER_ALLOW
                }

                webViewClient = object : WebViewClient() {
                    override fun shouldOverrideUrlLoading(
                        view: WebView?,
                        request: WebResourceRequest?
                    ): Boolean {
                        val uri = request?.url ?: return true

                        return if (uri.host == "service.example.com") {
                            false
                        } else {
                            // 외부 URL은 Custom Tab 또는 외부 브라우저
                            true
                        }
                    }
                }

                webChromeClient = WebChromeClient()

                loadUrl(url)
            }
        },
        modifier = Modifier.fillMaxSize()
    )
}

Manifest에서는 HTTP 접속을 막는 것이 기본입니다.

<application
    android:usesCleartextTraffic="false">
</application>

WebView에서 신뢰할 수 없는 콘텐츠를 불러올 가능성이 있다면 HTTPS만 허용하는 것이 공식 권고입니다.

현업에서 반드시 챙기는 부분
URL 화이트리스트

이것만 비교하면 위험합니다.

url.contains("example.com")

이런 주소도 통과할 수 있기 때문입니다.

https://example.com.attacker.com

반드시 파싱한 host를 정확히 비교합니다.

private fun isAllowedUrl(uri: Uri): Boolean {
    return uri.scheme == "https" &&
        uri.host == "service.example.com"
}

서브도메인까지 허용한다면:

private fun isAllowedHost(host: String?): Boolean {
    return host == "example.com" ||
        host?.endsWith(".example.com") == true
}

단, 점을 포함한 ".example.com"으로 검사해야 합니다.

외부 링크 분리
내 서비스 주소 → WebView 내부
외부 사이트 → Custom Tabs
전화·메일 → Android Intent

WebView를 범용 브라우저처럼 만들려고 하면 로그인, 팝업, 다운로드, 권한, 새 창 처리까지 일이 급격히 늘어납니다.

파일 업로드

웹의 다음 태그:

<input type="file" accept="video/*">

Android에서 WebChromeClient.onShowFileChooser()를 구현해야 제대로 작동합니다.

뒤로 가기
if (webView.canGoBack()) {
    webView.goBack()
} else {
    finish()
}

요즘은 OnBackPressedDispatcher나 Compose의 BackHandler로 연결합니다.

로그인

자체 서비스의 로그인 화면은 WebView에 넣을 수 있지만, Google 같은 외부 인증 제공자의 로그인은 Custom Tabs 쪽이 안전합니다. Google 공식 문서도 제3자 로그인은 브라우저와 격리되는 Custom Tabs 사용을 권장합니다.

로컬 React 빌드를 앱에 넣는 방식

웹서버에 접속하지 않고 React 빌드 결과를 APK에 넣을 수도 있습니다.

app/src/main/assets/
 ├─ index.html
 ├─ assets/
 │   ├─ index.js
 │   └─ index.css

이때 단순한:

webView.loadUrl("file:///android_asset/index.html")

보다는 WebViewAssetLoader가 권장됩니다.

val assetLoader = WebViewAssetLoader.Builder()
    .addPathHandler(
        "/assets/",
        WebViewAssetLoader.AssetsPathHandler(context)
    )
    .build()

그리고 다음과 같은 HTTPS 형태로 불러옵니다.

https://appassets.androidplatform.net/assets/index.html

이 방식은 file://보다 동일 출처 정책과 웹 리소스 처리가 자연스럽습니다.

지금 만들기 좋은 최소 버전

처음부터 브리지까지 크게 만들기보다 이 정도가 좋습니다.

1. React 웹서버 주소를 WebView에서 연다.
2. 허용 도메인만 내부에서 연다.
3. 외부 주소는 Custom Tabs로 넘긴다.
4. 뒤로 가기를 연결한다.
5. 파일 선택 기능만 네이티브로 구현한다.
6. 필요할 때 메시지 브리지를 추가한다.

지금 상황에서는 React 화면을 WebView로 띄우고 Android는 파일 선택과 공유만 담당하는 형태가 가장 현업스럽고 구현 대비 효과도 좋습니다.
